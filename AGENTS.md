# Repository Guidelines

## Project overview

Base Rollup is an Obsidian plugin that registers a custom Bases view type (`rollup-table`). The view renders query results in a table with grouping and column resizing, and writes an aggregate value back to the frontmatter of the note that embeds the Base.

## Development

- Source files live in `src/`.
- `src/main.ts` — plugin registration and lifecycle only.
- `src/RollupBasesView.ts` — view rendering and target property update logic.
- `src/constants.ts` — shared constants (view type, option keys, defaults).
- `src/types.ts` — type definitions (`Aggregation`).
- `src/options.ts` — view option definitions passed to `registerBasesView`.
- `src/property.ts` — aggregation computation and target property helpers.
- This project uses **pnpm**. Run `pnpm build` before committing, `pnpm build:prod` for release artifacts.
- Dev builds use plugin ID `base-rollup-dev` and name `Base Rollup (dev)`.
- Production builds use plugin ID `base-rollup` and name `Base Rollup`.
- Lint with `pnpm lint`, format with `pnpm format` (Biome).
- Husky runs a pre-commit hook.

## Release files

Obsidian loads these files from the plugin root:

- `manifest.json` — generated at build time from `manifest.config.ts`.
- `main.js` — generated by Vite, output to `dist/`.
- optional `styles.css` if added later.

Both `manifest.json` and `main.js` are generated by the build and should be committed for releases.

## Git

- Use focused commits.
- Follow Conventional Commits unless the repository history clearly uses another style.
- Do not use `git add .`; stage only relevant files.
